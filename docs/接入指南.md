# TrellisForge 嵌入式 C 接入指南

## 目的和边界

本指南将 TrellisForge 的项目级覆盖层接入一个已经是 Git 仓库的嵌入式 C
项目。它参考既有 Trellis/Grill Me 接入方案，并包含后续补充的子代理效率
约束。原始参考指南不会被本工程修改。

TrellisForge 不是 Trellis 的私有分叉：先运行 `trellis init`，再覆盖项目级
文件。不要从范例复制 `.trellis/tasks/`、`.trellis/workspace/`、`.trellis/.runtime/`
或 `.trellis/.template-hashes.json`；这些都是目标仓库自己的运行状态。

## 目录说明

```text
templates/embedded-c-overlay/
  AGENTS.md.template                         项目规则与 Trellis 入口模板
  .trellis/                                  工作流、门禁脚本、channel 代理、Spec 骨架
  .agents/skills/                            Grill Me 和两个项目级 Skill
  .claude/                                   Claude Code 代理、Hook、设置
  .codex/                                    Codex 代理、Hook、设置
tools/install-embedded-c-overlay.ps1         安装和占位符替换脚本
```

`__PROJECT_PREFIX__` 是目录名占位符，例如 `motor`；`PROJECT_PREFIX` 和
`PROJECT_NAME` 是文件正文中的占位符。安装脚本会同时替换三者。

## 接入步骤

1. 进入目标仓库根目录，阅读已有 `AGENTS.md`，并记录 `git status --short`。
   不覆盖用户已有变更。
2. 在目标根目录运行 `trellis init`。它提供与当前 Trellis 版本匹配的基础
   runtime、内置 Skills 和默认文件。
3. 在 TrellisForge 根目录运行：

   ```powershell
   & .\tools\install-embedded-c-overlay.ps1 `
     -TargetRoot C:\work\example-firmware `
     -ProjectPrefix example `
     -ProjectName "Example Firmware"
   ```

   脚本默认拒绝覆盖既有文件；首次接入或已审查差异后加 `-Force`。它只覆盖
   清单中的项目级定制文件，不删除任何目标文件。
4. 将 `templates/embedded-c-overlay/AGENTS.md.template` 合并到目标根目录
   `AGENTS.md`。保留原有项目规则，将模板中的 `<...>` 全部替换为可验证的
   本项目事实。
5. 填写 `.trellis/spec/shared/`：至少完成仓库结构、构建命令、静态检查、
   硬件验证边界和不可修改的硬件合同。按模块增加包级 Spec，并在
   `.trellis/config.yaml` 配置实际 packages。
6. 对 Claude Code：确认 `.claude/settings.json` 已合并而非丢失项目原有
   hooks。对 Codex：确认仓库已信任、用户级 `[features].hooks = true`，并在
   `/hooks` 中批准项目 Hook。
7. 运行验证：

   ```powershell
   python -m unittest .trellis/scripts/tests/test_planning_gate.py
   python -m unittest .trellis/scripts/tests/test_active_task_session_isolation.py
   python -m py_compile .claude/hooks/*.py .codex/hooks/*.py
   git diff --check
   ```

8. 创建一个仅文档的小任务，确认规划收敛、用户后续批准、`task.py start`、
   implement/check 派发与 Hook 注入均按预期工作后再用于产品代码。

## TrellisForge 修改了什么

| 位置 | 修改 | 目的 |
| --- | --- | --- |
| `.trellis/workflow.md` | 将 brainstorm、Grill Me、项目 adapter、审查 profile 接入状态路由 | 让规划、实施、审查有明确阶段边界 |
| `.trellis/scripts/common/planning_gate.py` 及相关脚本 | 校验 `planning_ready` 与 `plan_approved` | 没有收敛和后续用户批准不能进入实施 |
| `.agents/skills/*-trellis-grill-adapter` | 决策所有权与规划文档持久化 | 不为已知事实制造澄清问题 |
| `.agents/skills/*-trellis-review` | `light/standard/strict` 审查范围 | 审查只扩展到 diff、调用图、验收条件等证据支持的范围 |
| `.claude` / `.codex` Hook | 将任务 manifest、PRD、Spec、research 注入子代理 | 避免代理从零扫描任务上下文 |
| implement/check 代理与 Hook prompt | 批量 Read/Grep、合并相关 Edit、分阶段验证、修复后仅复验受影响检查、满足条件即停止 | 减少碎片化工具轮次和重复思考 |

这些效率规则没有 prompt 字符数/token 硬上限，不会因为复杂任务长就截断、
拒绝或强迫压缩需求。它们也不删除主代理的独有决策：Hook 注入的上下文优先，
子代理在缺失、截断、过期或必须核对精确行时可补读。

当前版本仍保留主代理 `original_prompt`，以免误删未被自动注入的关键要求。
因此主代理应遵守 workflow 的派发边界：只下发目标、范围、非目标、已有验收
条件和既有验证命令，不粘贴完整 PRD、Spec、research、清单或 diff。未来若要做
运行时去重，应只删除能精确证明与注入文件正文完全相同的副本，不能按总长度
截断 prompt。

## 嵌入式 C 特化项

该范例假定代码可能受中断、DMA、Flash、寄存器、启动文件、链接脚本和板级
验证约束。模板因此要求：

- 项目规则明确受保护的引脚、DMA、时钟、Flash、协议、调度周期和构建输入；
- 构建与静态检查使用项目真实命令，不虚构 Web 的 lint/typecheck；
- 构建、静态检查、单元测试和实体硬件验证分开报告；
- 变更 ISR、共享状态、持久化、协议或硬件合同必须扩大到直接调用者和相关 Spec；
- 新函数的注释说明单位、范围、阻塞性、中断上下文、可重入性及硬件副作用。

这些规则写在 `AGENTS.md.template`、两个项目级代理定义和
`spec/shared/*.md` 中。接入时必须把占位符改成真实工具链、目标板和约束；
不能把范例当作对所有 MCU 都正确的硬件事实。

## 换用其他语言时改哪里

工作流的规划门禁、任务上下文注入、批量探索、分阶段验证、停止条件和审查
profile 是语言无关的，可以保留。必须替换以下 C 特化内容：

1. `AGENTS.md`：删除 MCU/ISR/DMA/Flash/寄存器约束，写入该语言的并发、
   依赖、迁移、兼容性和发布约束。
2. `.agents/skills/__PROJECT_PREFIX__-trellis-review/SKILL.md`：替换嵌入式
   风险检查与验证报告字段。例如 Web 写 `lint/typecheck/unit/e2e`，Java 写
   `compile/test/integration/static-analysis`。
3. `.trellis/agents/implement.md` 和 `check.md`：将“嵌入式 C 检查、目标构建、
   硬件验证”换成项目实际检查，并同步报告格式。
4. `.claude/agents/trellis-*`、`.codex/agents/trellis-*` 和两个
   `inject-subagent-context.py`：把“不要发明 Web 命令”的 C 特化表述改为
   实际语言命令策略。
5. `.trellis/spec/shared/`：用语言和架构对应的代码规范、测试策略、部署/迁移
   合同替换嵌入式模板。

不要仅替换构建命令而保留 ISR、DMA、硬件验证等术语，否则审查代理会得到错误
的任务模型。

## 维护与升级

Trellis 更新可能覆盖由上游管理的文件。升级前保存 `git diff`，升级后重新应用
TrellisForge 覆盖层并逐项审查冲突。项目级 Skill 名称必须保留前缀，避免与
Trellis 内置 Skill 同名。每次改动 Hook 或 agent prompt 后至少运行 Python
语法校验、TOML/JSON 解析、`git diff --check` 和一次真实的小任务冒烟测试。
